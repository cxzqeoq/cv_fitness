# CV Fitness

Браузерный тренажёр позы: скелет поверх видео, сравнение движения с эталоном, сходство в процентах. Всё считается локально в браузере.

## Запуск

ПК:

```
python pose_serve.py
```

Открыть `http://localhost:8000`.

Телефон (камера требует HTTPS):

```
pip install segno
python pose_qr.py
```

На экране появится QR — отсканируй его телефоном, камера заработает сразу. `python pose_qr.py --local` — QR для LAN-адреса (без камеры).

## Режимы

- **Один** — скелет поверх своего видео: стили, фон, сглаживание, запись результата.
- **Сравнение** — эталон A против повтора B (файл или камера телефона). Оцениваются углы тела, итог — сходство в процентах. Плюс повторы/удержания, счёт и тиры, профиль упражнения по эталону, экспорт CSV.

## Архитектура

ES-модули, всё в браузере:

- `js/main.js` — точка входа: вкладки, хоткеи, пресеты.
- `js/model.js` — загрузка MediaPipe-модели (CDN или локальный `.task`).
- `js/features.js` — углы-фичи, видимость, форма-гейт, веса, сессия.
- `js/dtw.js` — выравнивание временных рядов (`dtwAlign`, `liveMatch`, `bestInWindow`).
- `js/qc.js` — оценка шума `σ_noise` и честная шкала сходства (`simReported`).
- `js/score.js` — счёт, тиры, комбо, повторы/удержания, графики.
- `js/compare.js` — режим «Сравнение»; `js/singles.js` — режим «Один».
- `js/render.js` — отрисовка скелета; `js/config.js` — константы; `js/utils.js` — утилиты; `js/state.js` — общее состояние.
- `pose_serve.py` — статический сервер; `pose_qr.py` — QR и HTTPS-туннель для телефона.

Поток данных: видео/камера → MediaPipe (`model.js`) → углы (`features.js`) → выравнивание (`dtw.js`) → шкала сходства (`qc.js`) → счёт и тиры (`score.js`).

## Без сети

Скачай `pose_landmarker_lite.task` (float16) и укажи его во втором поле файла первого режима.

## server/ — бэк и админка

Отдельный сервис поверх того же движка: заливка видео → серверная обработка
(MediaPipe по кадрам, авто-сегментация на упражнения, генерация превью и
описаний) → админка для редактирования → лёгкий плеер со скелетом-оверлеем
для просмотра без мощного телефона.

```
cd server && docker compose up -d
```

Публичный лендинг — `http://localhost:8000`, кабинет тренера — `/app`.
Предпросмотр готового видео — `/app/preview/{id}`; после публикации создаётся
отзывная публичная ссылка `/watch/{token}`. Стек, архитектурные решения и
известные грабли — в `CLAUDE.md`.
Меню «Экспорт» на странице готового видео скачивает субтитры в SRT и полную
разметку сегментов в JSON. Для SRT используется текст субтитра, затем описание
или название упражнения, если отдельный субтитр не заполнен.

Форма «Подключить пилот» не ведёт отдельную базу заявок: сервер создаёт lead/deal
через company-scoped endpoint `omra.crm`. Для неё нужны `CRM_BASE_URL` и
`CRM_PILOT_API_KEY`; ключ компании нельзя подменять глобальным CRM API key.

В списке видео доступны пакетные действия: публикация, повторная обработка и
удаление. Активные задания нельзя выбрать. Повторная обработка заменяет трек,
сегменты, описания и превью; опубликованная ссылка снова заработает после
успешного завершения.

Раздел `/students` хранит карточки учеников, контакты, заметки и архивный
статус. Готовое видео можно назначить ученику с датой и названием упражнения.
Назначение проходит состояния «назначено» → «в работе» → «на проверке» →
«завершено»: ученик запускает тренировку и отправляет комментарий, тренер
видит результат в карточке ученика, отвечает, завершает тренировку или
возвращает её в работу. Отдельно тренер оценивает всю тренировку и сегменты по
технике, амплитуде, стабильности, темпу и симметрии по шкале 1–5. Черновики
видны только в админке; итоговая оценка, заключение и рекомендации появляются
в плеере ученика. Карточка показывает текущий прогресс, историю и средний балл.

Раздел `/exercises` хранит каталог упражнений с инструкциями и допуском угла.
Любой готовый сегмент можно назначить эталоном, а остальные сегменты привязать
к упражнению и сравнить с ним. Сервер выравнивает временные ряды углов через
DTW, отдельно показывает сходство движения и темпа, а также оценки по суставам.
Сравнение использует компактный 2D-трек: эталон и повтор нужно снимать с
одинакового ракурса. Результат описывает сходство движения, а не медицинскую
корректность техники; после изменения границ сегмента устаревший результат
удаляется.

Локальные параметры доступны в `/settings`: лимит загрузки, частота и точность
MediaPipe, инструкция для AI-описаний и показ скелета в публичном плеере.
Значения хранятся в Postgres и сохраняются при перезапуске контейнера; ключ и
модель OpenRouter по-прежнему задаются только через `OPENROUTER_DSN`.

Административная часть закрыта авторизацией. Участники команды входят через
`omra.is`; email аккаунта должен совпадать с активным участником в разделе
«Команда». Роли применяются сервером: владелец управляет командой, настройками
и удалением, управляющий — учениками, оценками и публикациями, редактор —
обработкой видео, сегментами и упражнениями. Все изменяющие формы защищены
CSRF-токеном, а последние действия видны владельцу в журнале команды.

Ученики регистрируются отдельно по email и паролю на `/student/register`.
Пароли хранятся как Argon2id-хеши. В `/student` ученик видит только назначенные
ему тренировки, текущие статусы, историю и комментарии тренера. Видео открываются
через защищённые API без публичной ссылки.
Страницы `/students/{id}/progress` и `/student/progress` строят аналитику по
финальным оценкам: динамику среднего балла, изменение от первой к последней
тренировке, средние значения пяти критериев и агрегаты по упражнениям. Доступны
фильтры за 30, 90, 180, 365 дней или всё время и по конкретному упражнению.

Центры `/notifications` и `/student/notifications` показывают непрочитанные
события. Ученик получает новое назначение, комментарий, завершение или возврат
в работу; активные владельцы и управляющие получают отправленные на проверку
результаты. Счётчики видны в боковом меню тренера и в шапке кабинета ученика.
Прочтение подтверждается отдельной CSRF-защищённой кнопкой.


Схема Postgres управляется Alembic. Контейнер выполняет `alembic upgrade head`
до запуска Uvicorn; новые установки проходят все ревизии с нуля.

Очередь обработки однопроцессная. При запуске сервис автоматически возвращает
прерванные и ожидающие задания в очередь и обрабатывает их по порядку. Если
исходный файл исчез, задание становится ошибочным вместо бесконечного статуса
«обработка».
